# Paper Tour

A PDF paper reader that gives you a narrated, guided tour: the voice explains the paper while the
view scrolls, highlights the sentence being discussed, zooms into figures and boxes the part that
matters.

This repo is the scaffold: ingestion, the two JSON contracts, and a player that runs a
hand-written tour of *Attention Is All You Need*. The LLM tour writer, real TTS and voice Q&A
plug into these contracts later.

```
PDF ──▶ ingest/ingest.py ──▶ doc.json (IDs + coordinates) + figure crops
                                 │
             tour.json ◀── hand-written now, LLM-written later (refers to IDs only)
                                 │
                 player/ (pdf.js + SVG overlay + camera + narration)
```

## Layout

| Path | What |
|---|---|
| `schema/doc.schema.json` | Document model contract (output of ingestion) |
| `schema/tour.schema.json` | Tour script contract (input of the player) |
| `ingest/` | Python: PDF → `doc.json`, validation, ID outline for tour authors |
| `player/` | Vite + React + TypeScript player |
| `demo/attention/` | Demo paper: `tour.json` is committed; `paper.pdf` is downloaded and `doc.json` + `figures/` are generated by the quick start |

## Quick start

Needs Python 3.10+ and Node 18+. The paper is not in the repo, because its arXiv license doesn't allow re-hosting, so the
first line downloads it. `validate.py` checks that the download is the exact file the tour was written for.

```bash
curl -L -o demo/attention/paper.pdf https://arxiv.org/pdf/1706.03762v7
python3 -m venv ingest/.venv
ingest/.venv/bin/pip install -r ingest/requirements.txt
ingest/.venv/bin/python ingest/ingest.py demo/attention/paper.pdf --debug
ingest/.venv/bin/python ingest/validate.py demo/attention
cd player && npm install && npm run dev
```

Then open http://localhost:5174/?paper=attention (the static demo needs no Supabase).

- `ingest.py <pdf> [--out DIR] [--debug]` writes `doc.json` and `figures/` next to the PDF (or into
  `--out`). `--debug` also renders every page with all detected elements and their IDs drawn on
  top, into `_debug/page-NN.png`.
- `validate.py <paper-folder>` checks `doc.json` and `tour.json` against the schemas, and checks
  that every ID the tour uses exists in `doc.json`.
- `outline.py <paper-folder>` prints sections, figures and every sentence with its ID. Use it when
  writing a tour by hand; it is also the text an LLM tour writer will get.
- `check_tour.py <paper-folder>/tour.json <out-dir>` renders every step's targets the way the player
  frames them, one PNG per camera move, and prints the word each timed action fires on.
- `demo/attention/build_tour.py` is the source of the demo tour. Edit the narration and actions there,
  then run it to regenerate `tour.json`; it turns anchor words into `at_word` indexes.

Player keys: `Space` play/pause, `←`/`→` previous/next step, `D` toggles the ID overlay (click any
element in that mode to copy its ID). URL options: `?paper=<folder>`, `?silent=1` for timed narration
without speech, `?rate=4` to run faster while testing. `npm test` in `player/` runs the engine tests.

The plan, the current status and the open review findings are in `notes/`.

## The contracts

**The tour never contains coordinates.** It names elements by ID and the player looks up their
coordinates in `doc.json`. This is what makes LLM-written tours reliable: models pick IDs well and
bounding boxes badly. To point inside a figure without a panel ID, a tour gives a `region`
normalized to the target's bbox (`[0, 0, 0.5, 1]` is the left half).

Coordinates in `doc.json` are PDF points with the origin at the top-left of the page and y growing
downward (PyMuPDF's convention). A bbox is `[x0, y0, x1, y1]`.

| ID | Example | Points at |
|---|---|---|
| block | `p3.b2` | Text block 2 on page 3 (reading order) |
| sentence | `p3.s12` | Sentence 12 on page 3; `rects` has one rect per line fragment |
| section | `sec-3.2`, `sec-abstract` | The section's heading block |
| figure / table | `fig1`, `tab2` | The graphic or table body, by printed number, without the caption |
| panel | `fig2.a` | A sub-figure, in reading order |
| equation | `eq1` | A numbered display equation |
| page | `page4` | A whole page |

A tour is chapters of steps. Each step has narration (`say`) and actions. Actions fire at the
start of the step, or at word `at_word` of the narration. Overlays disappear when the step ends
unless `persist` is set; `clear` removes persistent ones.

| Action | Effect |
|---|---|
| `focus` | Scroll the target into view at reading zoom |
| `zoom` | Fit the target (or a `region` of it) to the viewport |
| `highlight` | Marker or underline on the text lines of each target |
| `box` | Outline with an optional label |
| `spotlight` | Dim everything except the target |
| `note` | Callout card next to the anchor |
| `clear` | Remove persistent overlays |

Narration uses the browser's speech synthesis until a step has pre-rendered `audio` (with
optional per-word timings), so the scaffold runs without API keys.

## Local library setup

For private PDF uploads and automatic Muse tours, use Node.js 22.12+ and Python 3.12:

```sh
npm ci
npm --prefix server ci
npm --prefix player ci
python3.12 -m venv ingest/.venv
ingest/.venv/bin/pip install -r ingest/requirements.txt
npm run supabase:start
npm run setup:local
```

Optionally set `MODEL_API_KEY` in the root `.env` for shared app access. Users can instead save
their own Meta key in **Profile & Settings**. Start the app:

```sh
npm run db:migrate
npm run dev
```

Open http://localhost:5174/. Model selection, API keys and prices are in **Profile & Settings**.
Automatic tours send paper text and rendered page/figure images to Meta.

```sh
npm run build
npm test
npm run test:integration
```

Integration tests require the local Supabase stack. `Dockerfile` and `compose.yaml` provide an
optional deployment setup; environment variables are listed in `.env.example`.
